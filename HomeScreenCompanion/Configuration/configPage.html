Home Screen Companion — Setup Guide

All features at a glance
What does this plugin do?
Home Screen Companion keeps your Emby home screen up to date automatically. Each source is a list of movies and shows: from a site like Trakt, MDBList or TMDb, from your own collections and playlists, picked by hand, built by filters on your files, written by an AI, or worked out per user from what they watch (Your Next Watch).
  • The plugin finds those titles in your library and keeps them up to date as a tag, an Emby collection and/or a playlist per user.
  • Any of them can be a home screen row for the users you choose, like "Trending Now" or "Christmas Movies", shown all year or only on the dates you set.
  • Top-lists show a list as a ranked row with numbered posters, like Netflix's Top 10.
  • Everything is refreshed on every sync: the daily scheduled task, or Run at the top of the page.

input Source Types
A source is where the plugin gets its list of movies or shows. Each source is linked to a tag — once the plugin has fetched the list, it marks matching titles in your Emby library with that tag. Choose the source type that suits how you want to build your list:
public External
Paste a list URL from Trakt, MDBList or TMDb; the plugin downloads the list and tags every matching title it finds in your library. More about External below.
video_library Local
Use an existing playlist or collection already in Emby as the source; every movie and show in it gets the configured tag. More about Local below.
format_list_numbered Manual List
Pick movies and shows by hand, right inside the plugin, in the order you want. More about Manual List below.
tune MediaInfo (Smart Playlist)
Build a list from the properties of your own files, e.g. "all 4K HDR movies" — including Popular on this server: most-watched titles by number of viewers. More about MediaInfo below.
auto_awesome AI created lists
Describe what you want in plain language — for example "Best sci-fi films from the 90s" — and let Anthropic Claude, Google Gemini, OpenAI (ChatGPT), any OpenAI-compatible service or a local Ollama model write the list. More about AI lists below.
recommend Personal: Your Next Watch
Personal recommendations, worked out on your server (no AI, no internet): every ticked user gets their own playlist of unwatched titles most like what they have been watching, refreshed on every sync. See Your Next Watch below for how it picks and how to set it up.
More about the source types
public
External — paste a list URL from Trakt, MDBList or TMDb. The plugin downloads the list and tags every matching title it finds in your library.
  • Several URLs — Add another URL adds more lists to the same source; their titles are combined under the one tag, collection and playlist. Links next to Source URLs open each site's list pages, to find lists.
  • Max (0=All) — each URL has its own limit. It counts titles found in your library (not blacklisted and passing the source's filters), from the top of the list: Max 10 on a top-100 list gives the 10 highest-ranked titles you have, even if titles 1–3 are missing. Up to 1,000 entries are read per URL.
  • Matching — titles are matched by their IMDb id, so your library items need IMDb ids (Emby's metadata usually adds them). A title on the list without an IMDb id is skipped. TMDb entries are looked up to find their IMDb id.
  • Trakt — needs a Trakt Client ID in the Settings tab. Public user lists work, and so do Trakt's own lists that its API offers, such as trakt.tv/movies/trending or /shows/popular.
  • MDBList — public lists work without a key; private lists need the MDBList API Key. MDBList's official lists (/lists/official/…) are always read without the key.
  • TMDb, two ways: your own lists — paste the URL of any public or private list you made on themoviedb.org; or API endpoints — paste a direct TMDb API URL (e.g. popular movies, top-rated, now-playing, or a specific collection). Both need a TMDb API Read Access Token in the Settings tab.
  • Test next to a URL checks that the list can be read; Preview shows which titles on the list are in your library and which are not.
  • If a site cannot be reached, the run log says why. Turn on Preserve tags and collections on empty result (Settings) to keep the old titles when a list comes back empty.
video_library
Local (Collection or Playlist) — use something that already exists in Emby as the list.
  • Choose Local Collection or Local Playlist, then pick it from the drop-down. Add another combines several; each has its own Max (0=All).
  • Movies and shows in it are used as they are. An episode in a playlist counts as its show.
  • Handy to give a hand-made collection a home row, art or a schedule, or to turn a playlist into a tag.
  • To show collections themselves as a row (instead of the movies inside), see Home Section — Collections mode.
  • The collection or playlist is found by its name: rename it in Emby and pick it again here. If it is not found, the run log warns about it.
  • Preview lists the titles that would get the tag.
format_list_numbered
Manual List — your own list, picked and ordered by hand.
  • Type in Add a movie or show to search your library and click a title to add it. ▲ ▼ move it, ✕ removes it.
  • The order is kept: a top-list made from the tag and a playlist follow it. An Emby collection still shows Emby's own sort order (see Keep the list order under Tags & Collections).
  • Titles later deleted from the library are skipped. Copy/paste matches the titles on another server by IMDb/TMDb/TVDb id.
  • Preview lists the titles that would get the tag, in your order.
tune
MediaInfo (Smart Playlist) — build a list from the properties of your own files, for example "all 4K HDR movies" or "Action films I haven't watched yet". It follows your library: titles that start or stop matching are added or removed on the next sync.
  • Filter by video quality, audio format, genre, actors, ratings, watch status and more — see MediaInfo Filters, including Popular on this server.
  • Max items (0 = all) caps the list. Preview (next to it) lists what matches right now.
  • A MediaInfo source without any rule is skipped (it would match the whole library) until it has one.
  • With the rule Media Type: Episode the filters check single episodes; the Tag tab then decides whether the episode, its season or its show gets the tag.
auto_awesome
AI created lists — write what you want, and an AI answers with a list of titles that the plugin then looks for in your library.
  • AI Provider — Anthropic Claude, Google Gemini, OpenAI (ChatGPT), Ollama (Local) or one of your OpenAI-compatible connections (listed by name). Each needs its key (or for Ollama its URL) and model under AI Settings in the Settings tab. Ollama is experimental: local models often know less about new titles and give wrong IMDb ids more often.
  • Prompt — just say what you want, e.g. "Feel-good comedies from the 80s". You don't need to ask for a format; the plugin's system prompt (Settings) already tells the AI how to answer.
  • Max items — how many titles you want. The AI is asked for more (up to twice as many) since some will not be in your library; the first ones found fill the list.
  • Matching — by the IMDb id in the AI's answer; when that id is missing or not in your library, by exact title and year.
  • Include recently watched for personalization — sends the chosen user's last watched titles (Recent items to include, default 20) with the prompt, for "recommended for you" lists. With Ignore titles only marked as watched (Settings) only real plays count.
  • Refresh every … days — 0 asks the AI on every full sync. A higher number keeps the last answer (tags, collection and playlist stay) until that many days have passed; the log says when it is due. This saves paid calls and keeps the list steady.
  • Test AI Source shows the AI's raw answer; Preview also shows which titles are in your library. Both make one paid call, and the next answer may differ.
filter_list
Filters on any source — every source type, not just MediaInfo, has Add filters (optional) at the bottom of its Source tab. The same rules as MediaInfo then narrow the list down, for example a Trakt list with only Unwatched titles, or only 4K ones. On External, Local and Manual sources the filters are applied before Max, so the limit counts only titles that pass; on an AI source they are applied to the titles found, which can leave fewer than Max items.
recommend Your Next Watch
The Personal: Your Next Watch source makes a private playlist for each user with the unwatched movies and shows most like what that user has been watching. It is all worked out on your server — no AI, no internet — and refreshed on every sync.
person
One playlist per user — On the source's Playlist tab keep Create Playlist on (it starts on for this type) and tick the Target Users (Select all ticks everyone). Each ticked user gets their own playlist with their own picks, best first, named after the Playlist Name (or the Display Name when empty). Untick a user and their playlist is removed on the next sync. Older setups kept the users on the Home Screen tab; they are copied to the Playlist tab automatically, once (after that the Playlist tab's users stay as you set them, also when you clear them all).
history
What it learns from (taste) — for each user:
  • the titles they finished in the last 90 days (the source's History window) — or, when that is fewer than 30, their last 50 finished titles; a show counts once they watched an episode;
  • their favourites and titles they rated 7 or higher (watched at any time);
  • recent titles count a little more than older ones; titles they rated low (below 5) are left out.
With Use favourites and ratings off, favourites and ratings play no part: only what was watched counts, and unwatched favourites are not suggested. Watched = marked played in Emby (past 90% or Mark played); started or stopped plays don't count.
filter_alt
What it can pick — movies and shows the user can open (their library access and parental rating apply), that they have not watched or started, one per film (a second version of the same film is never picked). Blacklisted titles and the source's own filters (for example Media Type to keep it to movies or shows) apply too.
join_inner
How a title scores — what it has in common with the user's taste:
  • Genres — weighted by how much more the user watches a genre than the library carries it (capped), so a few stray episodes of a rare genre don't take over;
  • People — the top-billed actors, directors and writers;
  • Studios and tags (tags made by HSC sources and top-lists are ignored);
  • rare people, studios and tags count more than common ones;
  • a similar year, a good community rating, and a "people like you" bonus for titles watched by the users who watched the most of the same titles.
link
Strong matches win — each title is also compared with the one watched title it has most in common with. Several kinds of match (for example genres and actors and studio or keywords) beat a single one — one shared actor or one broad genre is not enough for the top 10. Another film of a franchise (TMDb collection) the user is watching always counts as a strong match.
format_list_numbered
How the list is built — best first, with limits so it stays varied: a few titles per franchise and per main genre, and a movie/show mix that follows what the user watches. Unwatched favourites are included as titles the user wants to watch, but at most 3 in the top 10 and about 30% of the list, spread through it. Max items (default 50) sets the length.
fiber_new
New users (little history) — a user with fewer than 3 titles to learn from gets the server's most watched titles of all time that they have not seen — a different mix of the top titles for each user, changing daily, so new users don't all get the same list.
home
Show it on the home screen — turn on the Home Screen tab, tick the users who get the row and choose Section Type This source's playlist (each user's own): each of them sees their own playlist (a user needs a playlist, so tick them on the Playlist tab too). Copy & Sync copies the row to each target user pointing at their own playlist; users without one don't get the row. A show goes into the playlist as its first episode, because Emby playlists hold episodes, not whole shows; on the row its card still shows the show's poster (Image Type Primary; choose Thumb for the landscape image). Sort By (Default) keeps the playlist order, best match first; Random shuffles the row every time the home screen loads, so it shows a different 10 of the 50 each time (the playlist itself keeps its order).
sync
Refreshed every run — the lists are worked out again on every sync (and by Run Group), so they follow what each user watched since.
tab
Its other tabs — it has the same tabs as every other source. Preview lets you pick a user and shows their list with the reason for each title. Apply Tag and Create Collection start off for this type and work when turned on, but a tag or collection is shared by everyone: it gets the titles picked for the most users, not each user's own picks (a warning shows when you turn one on). The Playlist tab's Playlist look gives every user's playlist the same poster, background and description instead of Emby's automatic collage of four posters; a generated style is drawn from the titles picked for the most users, and an empty description gives "Picked just for you from what you've been watching — fresh recommendations every day."

What is a tag? — A tag is an invisible label that Emby can attach to a movie or show. You won't see it while browsing normally, but the plugin uses it to know which items belong to which list. Tags are what makes home screen rows work — a row simply shows all items that carry a certain tag.

Keep the list order — movies only (experimental) — shown when Ranked collections is switched on under Advanced Settings in the Settings tab (and saved). The collection then opens in the order of the list instead of Emby's own order.

analytics MediaInfo Filters
MediaInfo lets you build a list based on the properties of your own files — think of it as building a smart search. For example: "all 4K Dolby Vision movies in the Action genre that I haven't watched yet."
How rules work:
  • Each rule checks one property against a value (e.g. Genre = Action).
  • Rules in the same group can be combined with AND (must match all) or OR (match any one).
  • Multiple groups can also be combined with AND / OR using the connector between them.
  • The NOT button on a rule inverts it — e.g. NOT Genre: Comedy matches everything except comedies.
  • For text fields (Genre, Actor, Title…), enter one value per line. Any matching line triggers the rule.
  • Text fields offer Contains (partial match) or Exact (full match) mode.
  • Number fields (Year, Rating, Runtime…) support = > ≥ < ≤.
Video
Resolution (4K, 1080p, 720p, SD, 8K), Video codec (HEVC/H.265, AV1, H.264), HDR type (HDR10, Dolby Vision, HLG)
Audio
Format (Atmos, DTS-HD MA, TrueHD, DTS, AC3, AAC), Channels (7.1, 5.1, Stereo, Mono), Audio language — one language code per line (e.g. swe, eng)
Content
Genre, Actor/Cast, Director, Writer, Studio, Title, Episode Title, Plot overview, Tag (existing Emby tag), Content rating (PG-13, R…), IMDB ID, Collection, Playlist — one value per line; any match = rule matches
Music
Artist, Album. Use MediaType: Audio to target songs or MediaType: MusicVideo for music videos. Also supports Bit Rate, Sample Rate, Bits Per Sample, Track Number, Disc Number with numeric operators.
Metrics
Community Rating, Release Year, Runtime (minutes), Date Added (days ago), Date Modified (days ago), File Size (MB) — all support numeric operators
Activity
Watched / Unwatched, Last Played (days ago), Play Count, Watched By Count (how many users have finished it) — can be scoped to any user, all users, or a specific user. Popular on this server (viewers) — how many different users watched it in the last 7, 14, 30, 60, 90 or 180 days, the last year, or all time (default ≥ 3)
trending_up
Popular on this server — most-watched titles by number of viewers. Rule Popular on this server (viewers) under Activity: pick a time window (last 7, 14, 30, 60 or 90 days, last 6 months, last year or all time; default last 30 days), an operator and a viewer count (default >= 3).
  • A viewer is a user who has the title marked played in Emby (watched past 90% or Mark played) with their last play inside the window. Started or stopped plays don't count. Each user counts once, however often they watched it.
  • For a show, anyone who watched any episode counts as one viewer of the show. A film with several versions counts once: a user who watched any version is one viewer.
  • Emby only remembers each user's last play of a title, so a user who watched it before the window and not since doesn't count; titles marked watched without a date only count for All time. Disabled users are not counted.
  • Marking a title watched by hand looks the same to Emby as playing it. Turn on Ignore titles only marked as watched (Settings) to count only real plays here and in Last Played rules.
  • The source lists its matches most viewed first (ties: higher community rating, then by name), so Max items keeps the most popular ones, and a top-list made from the tag follows that order. With more than one Popular rule, the first one sets the order.

The Clear all filters button (bin icon) empties the filter list.

build_circle Troubleshooting
Start with Logs: the Sync tab says per source how many titles the list had, how many were found in your library and why a source was skipped or came back empty.
tv_off
The row doesn't show on the home screen
  • Go through the checklist in Quick Start (step 4).
  • Is the source active and inside its schedule? Outside it a tag row is empty, and Emby hides empty rows.
  • Does the row have titles for this user? Their library access and parental rating apply, and Playstate: Unplayed hides what they have watched.
  • A Single Collection row needs Create Collection, a Dynamic Media (tag) row needs Apply Tag, and a playlist row needs the user ticked on the Playlist tab.
rule
Fewer titles than expected (a ⚠ chip such as "9 of 10" on the source)
  • Titles that are not in your library are left out: Preview lists them under Not in your library, and Log missing movies and shows (Settings) puts them in the log.
  • External lists match by IMDb id. A movie you do have but without an IMDb id in Emby is not found: open it in Emby, check its metadata (Identify or Refresh metadata) and run again.
  • The source's filters and Blacklist also take titles out, and every URL has its own Max.
cloud_off
A source came back empty, or its tags disappeared
  • The log says why, e.g. a missing or wrong key, a private list, or a site that could not be reached. Check the key under External list settings and use Test next to the URL.
  • Turn on Preserve tags and collections on empty result so a failed fetch keeps the old titles instead of removing them.
  • A source saved without a URL (or with nothing picked) is skipped and changes nothing.
smart_toy
An AI list is empty or odd
  • Test AI Source shows the raw answer, or the error (a wrong key or model name is the usual cause).
  • An edited system prompt can make the answer unreadable: Reset to default under Edit system prompt.
  • A wrong title matched by name? Put its IMDb id in the source's Blacklist, or make the prompt more specific.
  • The list doesn't change? Refresh every keeps the last answer until it is due.
hourglass_top
Nothing happens after Save, or a run seems stuck
  • Save only stores the settings: changes reach Emby on the next run. Use Run Group on the source, or Run.
  • Runs wait for each other; Last run at the top shows what is running and what is waiting.
  • Dry Run Mode (Settings) left on? Then nothing is changed.
  • Emby apps keep posters and the home screen for a while: refresh, or sign out and in again.
bug_report
Still stuck? Click Report a Bug at the top of the page: it links to GitHub Issues and the plugin's Emby forum thread. Say what you expected, what happened, the source type and settings, and attach the zip from Download logs in the log window – soon after the problem, as the log keeps 7 days.
